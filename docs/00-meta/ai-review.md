# 本文のレビュー（AI）

`check` は**構造**を見る。リンクが繋がっているか、依存の向きが正しいか、
必須の節があるか。**文章として読めるかどうかは見ていない。**

そこを人の代わりに読ませるのが `review` である。

```bash
python -m tools.graph review --limit 3
python -m tools.graph review --focus DOM-01
python -m tools.graph review --format json
```

## check とは別物である

**一緒にしてはいけない理由がある。**

| | `check`（G001〜G014） | `review`（A001〜A006） |
| --- | --- | --- |
| 結果 | **同じ入力なら同じ結果** | **同じ入力でも変わりうる** |
| 通信 | しない | **する** |
| 外部の鍵 | 要らない | `ANTHROPIC_API_KEY` が要る |
| 費用 | かからない | **かかる** |
| CI | 回す | **回さない** |
| 終了コード | 問題があれば 1 | **常に 0** |

`G0xx` という番号は「再現して、CI が強制するルール」という意味を持っている。
**再現しない指摘に同じ番号を与えると、番号の意味が壊れる。**
だから `A0xx` という別の名前空間にしてある。

**`check` は今までどおりオフラインで完結する。** 鍵を設定しても `check` は
通信しない。`review` を呼んだときだけ外に出る。

## 指摘コード

| コード | 内容 |
| --- | --- |
| `A001` | 曖昧表現 |
| `A002` | 冗長表現 |
| `A003` | 用語の不統一（`G013` が届かない範囲） |
| `A004` | 必須説明の欠落・粒度の不揃い |
| `A005` | 「前提 → 本文 → まとめ」の構造が成立していない |
| `A006` | このノードが何を説明するものか不明瞭 |

`A003` が要るのは、`G013` に**届かない範囲があると分かっている**ため
（上位層、兄弟ノード。[META-01](./graph-rules.md) を参照）。
`review` には依存先の用語表を渡してあるので、完全一致では拾えない揺れを見てもらえる。

## 何を送っているか

- 対象ノードの**本文**（フロントマターと自動生成ブロックを除く）
- `id` / `type` / `title`
- 依存先の**用語表**（禁止された言い換えの一覧）

**送るのは 1 ノードずつ。** グラフ全体は送らない。

**既定では 10 ノードまでしか送らない**（`--limit`）。`--limit 0` で全件になるが、
ノード数だけ API を呼ぶので費用がかかる。実行前に**何件送るかを必ず表示する。**

## 従う義務はない

出てくるのは**助言**であって検査ではない。

- 内容の正しさは判断できない。**書かれている事実は正しいものとして扱わせている**
- 構造の誤りは指摘させていない。それは `check` の担当
- 好みの問題は指摘しないよう指示してあるが、**完全には防げない**

**指摘が 0 件でも品質の保証にはならない。**
逆に、指摘があっても直す必要があるとは限らない。

## 鍵が無いとき

何もせずに終わる。**グラフの問題ではないので失敗にしない。**

```
ANTHROPIC_API_KEY が設定されていないため、レビューを行いません。
これはグラフの問題ではありません。check は影響を受けません。
```

## CI で回さない理由

1. **再現しない。** 同じコミットで通ったり落ちたりする CI は信用されなくなる
2. **費用がかかる。** push のたびに全ノードを送ることになる
3. **鍵が要る。** 派生リポジトリごとにシークレットの設定が必要になる
4. **通信する。** `check` がオフラインで完結するという性質を失う

必要なときに人が手で回す。**書いている最中に 1 ノードだけ見てもらう**のが主な使い方である。
